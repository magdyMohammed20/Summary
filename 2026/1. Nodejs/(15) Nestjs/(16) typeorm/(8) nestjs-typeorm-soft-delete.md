## 1. What is Soft Delete?

Instead of permanently removing a row from the database, soft delete **marks it as deleted** by setting a `deletedAt` timestamp.

```
Hard Delete → row removed from DB forever ❌
Soft Delete → row stays in DB, deletedAt is set ✅
```

```sql
-- hard delete
DELETE FROM items WHERE id = 1

-- soft delete
UPDATE items SET deletedAt = '2026-08-12 03:44:41' WHERE id = 1
```

> Soft deleted rows are **automatically excluded** from all queries unless you explicitly ask for them.

## 2. Setup

### Step 1 — Add `@DeleteDateColumn()` to `AbstractEntity`

Since all entities extend `AbstractEntity`, adding it here gives soft delete to **all entities automatically**.

```typescript
// database/abstract.entity.ts
import { DeleteDateColumn, PrimaryGeneratedColumn } from "typeorm";

export class AbstractEntity<T> {

    @PrimaryGeneratedColumn()
    id: number;

    @DeleteDateColumn()
    deletedAt: Date;  // null = active, has value = soft deleted

    constructor(entity?: Partial<T>) {
        Object.assign(this, entity);
    }
}
```

---

### Step 2 — Add `deletedAt` column to the database

The column must exist in the DB before using soft delete. Choose one option:

**Option 1 — Enable `synchronize` temporarily (quickest for dev)**

```typescript
// database/database.module.ts
import { Module } from '@nestjs/common';
import { ConfigModule, ConfigService } from '@nestjs/config';
import { TypeOrmModule } from '@nestjs/typeorm';

@Module({
    imports: [
        ConfigModule.forRoot(),
        TypeOrmModule.forRootAsync({
            imports: [ConfigModule],
            inject: [ConfigService],
            useFactory: (configService: ConfigService) => ({
                // ...other config
                synchronize: true, // 👈 enable temporarily — auto-adds deletedAt column
            })
        })
    ]
})
export class DatabaseModule { }
```

> Restart the app — TypeORM auto-adds `deletedAt` to all tables. Then set `synchronize: false` again.

**Option 2 — Generate and run a migration (recommended for production)**

```bash
# generate migration
npm run migration:generate src/migrations/AddSoftDeleteColumns

# run migration
npm run migration:run
```

**Option 3 — Add column manually in MySQL**

```sql
ALTER TABLE `items`   ADD `deletedAt` datetime(6) NULL;
ALTER TABLE `comment` ADD `deletedAt` datetime(6) NULL;
ALTER TABLE `listing` ADD `deletedAt` datetime(6) NULL;
```

> [!IMPORTANT]
> ### ⚠️ Which option to use?
>
> | Environment | Option |
> |---|---|
> | Development | `synchronize: true` — fastest, auto-syncs schema |
> | Production | Migration — safe, version-controlled, no data loss risk |

## 3. Soft Delete in Service

```typescript
// items/items.service.ts
async remove(id: number) {
    await this.entityManager.transaction(async (entityManager) => {

        const item = await entityManager
            .createQueryBuilder(Item, 'item')
            .leftJoinAndSelect('item.listing', 'listing')
            .leftJoinAndSelect('item.tags', 'tags')
            .where('item.id = :id', { id })
            .getOne()

        if (!item) {
            throw new NotFoundException(`Item #${id} not found`)
        }

        // op1 — hard delete tags from junction table
        //        (junction tables have no deletedAt column)
        await entityManager
            .createQueryBuilder()
            .relation(Item, 'tags')
            .of(id)
            .remove(item.tags)

        // op2 — soft delete comments
        await entityManager
            .createQueryBuilder()
            .softDelete()
            .from(Comment)
            .where('itemId = :id', { id })
            .execute()

        // op3 — soft delete item
        await entityManager
            .createQueryBuilder()
            .softDelete()
            .from(Item)
            .where('id = :id', { id })
            .execute()

        // op4 — soft delete listing (null check — listing may not exist)
        if (item.listing) {
            await entityManager
                .createQueryBuilder()
                .softDelete()
                .from(Listing)
                .where('id = :id', { id: item.listing.id })
                .execute()
        }
    })
}
```

> [!IMPORTANT]
> ### ⚠️ Tags junction table must be hard deleted
>
> The junction table (`items_tags_tag`) is auto-generated by TypeORM and has **no `deletedAt` column**.
> So tags must always be removed with a hard delete using `.relation().remove()` — not `.softDelete()`.
>
> ```typescript
> // ❌ Won't work — junction table has no deletedAt
> .softDelete().from('items_tags_tag')
>
> // ✅ Correct — hard delete from junction table
> .relation(Item, 'tags').of(id).remove(item.tags)
> ```

## 4. Restore

Restore brings a soft deleted record back by setting `deletedAt` back to `null`.

```typescript
async restore(id: number) {
    await this.entityManager.transaction(async (entityManager) => {

        // must use withDeleted() to find soft deleted items
        const item = await entityManager
            .createQueryBuilder(Item, 'item')
            .leftJoinAndSelect('item.listing', 'listing')
            .where('item.id = :id', { id })
            .withDeleted()  // 👈 include soft deleted rows
            .getOne()

        if (!item) {
            throw new NotFoundException(`Item #${id} not found`)
        }

        // op1 — restore comments
        await entityManager
            .createQueryBuilder()
            .restore()
            .from(Comment)
            .where('itemId = :id', { id })
            .execute()

        // op2 — restore item
        await entityManager
            .createQueryBuilder()
            .restore()
            .from(Item)
            .where('id = :id', { id })
            .execute()

        // op3 — restore listing
        if (item.listing) {
            await entityManager
                .createQueryBuilder()
                .restore()
                .from(Listing)
                .where('id = :id', { id: item.listing.id })
                .execute()
        }
    })
}
```

**Add restore endpoint in controller:**

```typescript
// items/items.controller.ts
@Patch(':id/restore')
restore(@Param('id') id: string) {
    return this.itemsService.restore(+id)
}
```

## 5. Querying Soft Deleted Records

```typescript
// normal find — soft deleted rows excluded automatically
await this.itemRepository.find()

// include soft deleted rows
await this.itemRepository.find({ withDeleted: true })

// with QueryBuilder — include soft deleted
await this.itemRepository
    .createQueryBuilder('item')
    .withDeleted()  // 👈
    .getMany()

// find only soft deleted items
await this.itemRepository
    .createQueryBuilder('item')
    .where('item.deletedAt IS NOT NULL')
    .withDeleted()
    .getMany()
```

## 6. Hard Delete vs Soft Delete

| | Hard Delete | Soft Delete |
|---|---|---|
| Row in DB | ❌ Gone forever | ✅ Still exists |
| Recoverable | ❌ No | ✅ Yes via `restore()` |
| Storage | ✅ Saves space | ❌ Grows over time |
| Audit trail | ❌ No history | ✅ Knows when deleted |
| Query performance | ✅ Fewer rows | ❌ Must filter deletedAt |
| Use when | temp data, cache, logs | user data, orders, posts |

---

## 7. Summary

| Method | What it does |
|---|---|
| `@DeleteDateColumn()` | Adds `deletedAt` column to entity |
| `.softDelete()` | Sets `deletedAt` to current timestamp |
| `.restore()` | Sets `deletedAt` back to `null` |
| `.withDeleted()` | Includes soft deleted rows in SELECT |
| `.relation().remove()` | Hard delete from junction table (for ManyToMany) |

**Soft delete order (same as hard delete — children before parent):**
```
op1 → tags        (hard delete from junction table)
op2 → comments    (softDelete)
op3 → item        (softDelete)
op4 → listing     (softDelete — only if exists)
```

> **Rule of thumb:** Use soft delete for any data that might need to be recovered or audited — user accounts, orders, products, posts. Use hard delete for truly disposable data like temp files, sessions, or logs.
